## 1. Архитектура решения

```text
Руководитель
     |
     v
Оркестратор запроса
     |
     +--> Агент amoCRM
     |      сделки, этапы, суммы, ответственные,
     |      задачи, просрочки и история изменений
     |
     +--> Агент телефонии
     |      звонки, длительность, участники, записи,
     |      связь с клиентом или сделкой
     |
     +--> Агент обработки звонков
     |      аудио -> speech-to-text -> diarization ->
     |      темы, возражения, результат разговора
     |
     +--> Аналитический агент
            конверсия, скорость обработки, качество
            звонков, аномалии и рекомендации
                    |
                    v
             Отчёт с источниками
```

Оркестратор принимает естественно-языковой запрос, определяет период и запускает
сбор данных. Агент amoCRM работает через OAuth 2.0 и REST API: `/api/v4/leads`,
`/api/v4/tasks`, пользователей и этапы воронки. Агент телефонии получает события
через API оператора или webhook завершённого звонка. Связь звонка со сделкой
определяется по ID, номеру телефона или внешнему ID.

Обработка звонков выполняется асинхронно через очередь. Аудио временно хранится в
S3-совместимом хранилище, затем распознаётся и очищается от лишних персональных
данных. В аналитический контур передаются транскрипт и метаданные; срок хранения
исходного аудио задаётся политикой компании.

Результаты и версии расчётов хранятся в PostgreSQL. Для каждого вывода сохраняются
ссылки на исходные сделки и звонки, чтобы руководитель мог проверить результат.

## 2. Автоматизация, человек и риски

Система сама собирает данные, считает конверсию и просрочки, транскрибирует звонки,
проверяет разговоры по чек-листу, ищет сделки без следующего шага и формирует отчёт.

Человеку передаются рекомендации, влияющие на оценку сотрудников, спорные случаи с
низкой уверенностью модели, жалобы клиентов и любые необратимые действия в CRM.

Главные ограничения:

1. **Качество данных.** В CRM могут отсутствовать задачи, ответственные или связь
   звонка со сделкой.
2. **Ошибки распознавания.** Шум, акцент, перебивания и несколько участников
   влияют на транскрипт и оценку разговора.
3. **Безопасность.** Записи и номера клиентов требуют разграничения доступа,
   шифрования, аудита и ограниченного срока хранения.

## 3. Фрагмент интеграции с amoCRM

Метод получает сделки, изменённые за последние 30 дней, затем отдельным запросом
загружает задачи и оставляет сделки без задач или с просроченными задачами.

```python
import os
import time
import requests
from datetime import datetime, timedelta, timezone

BASE = f"https://{os.environ['AMO_SUBDOMAIN']}.amocrm.ru/api/v4"
HEADERS = {"Authorization": f"Bearer {os.environ['AMO_TOKEN']}"}

def api(path, params):
    r = requests.get(BASE + path, headers=HEADERS, params=params, timeout=30)
    r.raise_for_status()
    return r.json().get("_embedded", {})

def get_leads():
    since = int((datetime.now(timezone.utc) - timedelta(days=30)).timestamp())
    leads, page = [], 1
    while True:
        batch = api("/leads", {
            "page": page, "limit": 250,
            "filter[updated_at][from]": since,
        }).get("leads", [])
        if not batch:
            break
        leads += batch
        if len(batch) < 250:
            break
        page += 1
    return leads

def find_problem_leads(leads):
    now = int(time.time())
    result = []
    for lead in leads:
        tasks = api("/tasks", {
            "filter[entity_type]": "leads",
            "filter[entity_id][]": lead["id"],
            "limit": 250,
        }).get("tasks", [])
        overdue = [t for t in tasks
                   if not t.get("is_completed")
                   and t.get("complete_till", 0) < now]
        if not tasks or overdue:
            result.append({"id": lead["id"], "name": lead.get("name"),
                           "reason": "no_tasks" if not tasks else "overdue_tasks",
                           "task_ids": [t["id"] for t in overdue]})
    return result
```

## 4. AI-проект

**[BrowserPilot](https://github.com/gucci639/browser-ai-agent)** — универсальный
агент, который выполняет многошаговые действия в реальном Chromium без сценария
для каждого сайта. Он читает живой DOM, вызывает типизированные инструменты,
проверяет результат и передаёт человеку CAPTCHA, 2FA и необратимые действия.

**Стек:** Python 3.12, Playwright, OpenAI-compatible API, async control loop,
persistent browser context, structured DOM snapshots, retries и human-in-the-loop.

Результат — рабочий прототип, который умеет искать, переходить по страницам,
заполнять формы, работать с popup и восстанавливаться после устаревших селекторов.

## 6. Пример улучшения процесса

В сдельном проекте по обработке заявок менеджер вручную переносил обращения из
формы сайта в таблицу и проверял дубликаты. Я предложил webhook-сервис: он
нормализовал телефон, определял тип обращения, проверял дубликаты за 24 часа и
создавал сделку с задачей в CRM. Неуверенные случаи отправлялись менеджеру.

В результате ручной перенос исчез, новые заявки сразу попадали ответственному,
дубликаты отсеивались автоматически, а время от заявки до первого контакта стало
измеримым.
