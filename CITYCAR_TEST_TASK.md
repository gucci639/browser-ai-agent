## 1. Архитектура решения

Запрос руководителя: «Проанализируй работу отдела продаж за последние 30 дней».

```text
Руководитель
     |
     v
Оркестратор запроса
     |
     +--> Агент amoCRM
     |      - сделки, статусы, суммы, ответственные
     |      - задачи и просрочки
     |      - история изменений
     |
     +--> Агент телефонии
     |      - звонки за период
     |      - запись, длительность, участники
     |      - связь звонка со сделкой или номером клиента
     |
     +--> Агент обработки звонков
     |      - скачивание аудио
     |      - speech-to-text
     |      - разделение ролей менеджер/клиент
     |      - выделение тем, возражений и результата
     |
     +--> Аналитический агент
            - конверсия по этапам
            - скорость обработки лидов
            - просроченные задачи
            - качество звонков по чек-листу
            - сравнение менеджеров
            - поиск аномалий и повторяющихся проблем
                    |
                    v
             Отчёт руководителю
```

Агент amoCRM получает данные через OAuth 2.0 и REST API: сделки через `/api/v4/leads`, задачи через `/api/v4/tasks`, пользователей и этапы через соответствующие методы API. Для телефонии используется API конкретного оператора или webhook-события о завершённых звонках. По идентификатору сделки, номеру телефона или внешнему ID звонок связывается со сделкой в amoCRM.

Обработка звонков выполняется асинхронно через очередь задач. Аудиозапись скачивается во временное защищённое хранилище, затем проходит распознавание речи, diarization и очистку персональных данных. В аналитический контур передаётся транскрипт и метаданные звонка, а не исходный файл, если запись больше не нужна по политике хранения.

Результаты хранятся в PostgreSQL: исходные сущности, транскрипты, показатели, версии промптов и ссылки на источники. Аудио можно хранить в S3-совместимом объектном хранилище с ограниченным сроком жизни. Для повторных запросов используется кэш и заранее рассчитанные дневные показатели.

## 2. Что система делает сама и что передаёт человеку

Система сама:

- собирает сделки, задачи и звонки за период;
- считает конверсию, выручку, средний цикл сделки и просрочки;
- транскрибирует звонки и оценивает их по чек-листу;
- находит сделки без следующего шага;
- формирует отчёт с цифрами, выводами и ссылками на исходные данные;
- выделяет подозрительные случаи: резкое падение конверсии, много длинных звонков без результата, повторяющиеся возражения.

Человеку передаются:

- рекомендации, влияющие на мотивацию или оценку сотрудника;
- спорные случаи с низкой уверенностью модели;
- жалобы клиентов и потенциально конфликтные ситуации;
- решения о блокировке, удалении, изменении сделки или постановке задач;
- финальное утверждение управленческих действий.

Три главных риска:

1. **Качество данных.** В CRM могут отсутствовать задачи, быть неверно указаны ответственные или не связываться звонки со сделками.
2. **Ошибки распознавания и интерпретации.** Шум, акцент, перебивания и несколько участников снижают точность транскрипта и оценки разговора.
3. **Персональные данные и безопасность.** Записи разговоров и номера клиентов требуют ограниченного доступа, шифрования, аудита и понятного срока хранения.

## 3. Фрагмент кода Python

Код использует API amoCRM и возвращает сделки за последние 30 дней, у которых нет задач или есть невыполненные задачи с истёкшим сроком.

```python
import os
import time
import requests
from datetime import datetime, timedelta, timezone

BASE = f"https://{os.environ['AMO_SUBDOMAIN']}.amocrm.ru/api/v4"
HEADERS = {"Authorization": f"Bearer {os.environ['AMO_TOKEN']}"}

def get_leads():
    since = int((datetime.now(timezone.utc) - timedelta(days=30)).timestamp())
    page, result = 1, []

    while True:
        response = requests.get(
            f"{BASE}/leads",
            headers=HEADERS,
            params={
                "page": page,
                "limit": 250,
                "with": "tasks",
                "filter[updated_at][from]": since,
            },
            timeout=30,
        )
        response.raise_for_status()
        leads = response.json().get("_embedded", {}).get("leads", [])
        if not leads:
            break

        result.extend(leads)
        if len(leads) < 250:
            break
        page += 1

    return result

def without_or_overdue(leads):
    now = int(time.time())
    selected = []

    for lead in leads:
        tasks = lead.get("_embedded", {}).get("tasks", [])
        overdue = [
            task for task in tasks
            if not task.get("is_completed")
            and task.get("complete_till", 0) < now
        ]
        if not tasks or overdue:
            selected.append({
                "id": lead["id"],
                "name": lead.get("name"),
                "responsible_user_id": lead.get("responsible_user_id"),
                "status_id": lead.get("status_id"),
                "reason": "no_tasks" if not tasks else "overdue_tasks",
                "overdue_task_ids": [task["id"] for task in overdue],
            })
    return selected

if __name__ == "__main__":
    print(without_or_overdue(get_leads()))
```

Документация: [amoCRM Tasks API](https://www.amocrm.ru/developers/content/crm_platform/tasks-api), [amoCRM Leads API](https://www.amocrm.ru/developers/content/crm_platform/leads-api).

## 4. Реальный AI-проект

[BrowserPilot — GitHub](https://github.com/gucci639/browser-ai-agent)

Это универсальный AI-агент, который выполняет многошаговые действия в реальном Chromium-браузере через tool calling. Он анализирует живой DOM, находит видимые интерактивные элементы и выполняет действия: поиск, навигацию, ввод данных, работу с формами и подтверждение результата.

Стек:

- Python 3.12;
- Playwright;
- OpenAI-compatible API;
- асинхронный control loop;
- persistent browser context;
- structured DOM snapshots;
- retries и completion guards;
- human-in-the-loop для CAPTCHA, 2FA и необратимых действий.

Результат: агент работает с динамическими сайтами без заранее написанных сценариев для каждого сайта, сохраняет сессии и умеет восстанавливаться после ошибок интерфейса.

## 6. Пример улучшения в работе

На одном сдельном проекте нужно было автоматизировать обработку заявок из формы сайта. Изначально менеджер вручную переносил заявки в таблицу и отдельно проверял телефон, город и тип услуги. Из-за этого часть заявок обрабатывалась с задержкой.

Я предложил добавить промежуточный webhook-сервис: он принимал заявку, нормализовал телефон, определял тип обращения, проверял дубликаты за последние 24 часа и сразу создавал сделку с задачей в CRM. Неуверенные случаи отправлялись менеджеру на проверку.

После внедрения:

- ручной перенос заявок был убран;
- новые обращения стали попадать менеджеру сразу;
- дубликаты начали отсеиваться автоматически;
- менеджер тратил время только на спорные заявки;
- процесс стал измеримым по времени от заявки до первого контакта.
